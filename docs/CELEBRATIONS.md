# Team celebrations

My Workspace dashboard includes today's birthdays and work anniversaries and a next-seven-days list. Dates use the signed-in employee's configured timezone (America/New_York fallback). February 29 birthdays appear February 28 in non-leap years. Inactive accounts are excluded. Birthday payloads omit original dates, birth years, age, email and phone. Work anniversaries show completed service years, starting at one year.

Birthday sharing is enabled by default for saved dates. The dashboard no longer displays employee or administrator birthday visibility controls. Existing saved preferences are still honored by the feed and reaction endpoint; this UI update does not reset anyone's preference. Existing HR-only employee records remain accessible to HR. Both celebration boards omit birthday ages and birth years, including the admin widget's former “Turning…” and “Born on…” labels.

Today-only reactions support celebration, cake, heart and applause. Each active employee has one stored reaction per event occurrence; selecting another replaces it and selecting the active emoji removes it. Counts and named reactors are shared with signed-in employees. Hidden, inactive, future, past and invalid events cannot receive reactions. One grouped in-app notification per celebrant/date is created on the first teammate reaction, never one per click. Reactions refresh on focus and every minute while the dashboard is visible. No email or push notification is sent.

The redesigned board uses a warm birthday theme and a blue work-anniversary theme, with lightweight SVG cake/award artwork, a month/day date badge and subtle CSS motion. Today reads “It’s [Name]’s birthday today!” with “Your GO team wishes you a wonderful birthday!”; future birthdays read “Upcoming birthday: [Name]”. Anniversary headlines read “Happy 1st GO Anniversary!” (or 2nd, 3rd, 11th, 21st, etc.) with the employee's name, and upcoming headlines use “Upcoming [ordinal] GO Anniversary”. Both employee and admin boards share the ordinal formatter. Dates are displayed as month/day without a year. Anniversary years always mean completed years of service.

Multiple cards rotate every eight seconds and offer manual previous/next and an icon button to pause animation. The next-seven-days list opens selectable cards. Pointer/keyboard interaction, an open list or reaction details, and in-flight reactions pause rotation. Reduced-motion preference disables all animation and automatic rotation; hidden tabs also pause. A single card keeps its message still. No upcoming events yields a quiet empty state. Polls cannot overwrite an in-flight reaction with an older response.

Data persists in hr_v2_celebrationPreferences and hr_v2_celebrationReactions, through the existing serialized transaction adapter. GET reads only users, the current session and these two collections. Reaction writes also include notifications to preserve a grouped notification. Existing database rules/IAM still apply; endpoints require active authenticated accounts and first-login password change completion. Only admins can change someone else's birthday setting.
